🧠 Core Architecture: Tree + Event Session Manager
🔸 Purpose
Maintain stateless services

Persist session state, tree progression, and event history

Enable dynamic bot behavior across public, MSME, affiliate, and staff modes

🧱 Layered Breakdown
1. Bot Ingress Service
Consumes: incoming_messages Redis stream

Validates: payload structure, sender ID, channel

Resolves:

Bot type: default (public/register) or custom (customer/staff)

Mode: MSME, affiliate, staff

Enriches:

MSME/affiliate metadata

Bot session details

Tree state from event_session_manager

Publishes: to resolved_payload queue

2. Bot Intent Service
Consumes: resolved_payload queue

Validates: enriched payload

Resolves Intent:

Primary: Gemini

Fallbacks: rule-based, last node context

Publishes: to default_queue or custom_queue

3. Default Bot Service
Consumes: default_queue

Validates: payload and intent

Performs:

Maps intent to tree node

Activates subtree

Updates current_node:{session_id}

Stores tree in intent_tree:{session_id}

Publishes: to reply_queue

4. Custom Bot Service
Same as default, but scoped to MSME/staff logic

Uses MSME-specific tree and handlers

5. Bot Reply Service
Consumes: reply_queue

Validates: reply payload

Generates: Gemini-based reply

Publishes: to WhatsApp/SMS outbound queue
