Affiliate Multiplier Service (AMS)

1. Description:
Handles affiliate intent to upgrade their multiplier tier (Bronze, Silver, Gold) by initiating payment and attaching the multiplier once payment is confirmed. Ensures only paid affiliates receive tier-based boosts during affiliate pool payouts. Integrates with PaymentService, AffiliatePoolService, and RevenuePartitionService.

2. Features:
- Accept affiliate intent to upgrade tier
- Generate payment request for selected tier
- Listen for PaymentConfirmed event
- Attach multiplier to affiliate profile upon payment
- Emit MultiplierActivated event
- Expose current tier and multiplier for each affiliate

3. Schema:
Table: affiliate_multiplier_service.tier_payments
- id: UUID (PK)
- affiliate_id: UUID (FK → affiliate_service.affiliates.id)
- tier_requested: ENUM('bronze', 'silver', 'gold')
- amount_due: NUMERIC
- payment_status: ENUM('pending', 'confirmed', 'failed')
- payment_reference: TEXT
- created_at: TIMESTAMP
- updated_at: TIMESTAMP

Table: affiliate_multiplier_service.active_multipliers
- id: UUID (PK)
- affiliate_id: UUID (FK → affiliate_service.affiliates.id)
- tier: ENUM('bronze', 'silver', 'gold')
- multiplier: NUMERIC
- activated_at: TIMESTAMP
- expires_at: TIMESTAMP

4. Routes:
POST   /multiplier/intent                   → Submit intent to upgrade tier
GET    /multiplier/{affiliate_id}           → Get current multiplier and tier
POST   /multiplier/payment-confirmed        → Confirm payment and activate multiplier
GET    /multiplier/tiers                    → List available tiers and prices

5. External Outreach:
- Sends payment request to PaymentService
- Listens for PaymentConfirmed from PaymentService
- Emits MultiplierActivated to AffiliatePoolService and RevenuePartitionService
- Shares active multipliers with AnalyticsService

6. Background Work:
- Expiry check for expired multipliers
- Optional renewal reminders
- Tier price config sync
- Audit log of tier upgrades

10. Scalability Readiness:
- Current Target (1–500 affiliates):
  - Static tier pricing
  - Manual payment confirmation

- Ready for 1,000 affiliates:
  - Webhook-based payment confirmation
  - Redis cache for active multipliers

- Path to 10,000+ affiliates:
  - Sharded multiplier table
  - Event-driven multiplier activation
  - Autoscaling payment listener
  - Observability stack (Prometheus + Grafana)

11. Flowchart Reference:
- Affiliate → AMS (/multiplier/intent)
- AMS → PaymentService (create payment)
- PaymentService → AMS (PaymentConfirmed)
- AMS → AffiliatePoolService (MultiplierActivated)
- AMS → RevenuePartitionService (MultiplierActivated)
