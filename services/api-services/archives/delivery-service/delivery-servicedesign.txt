1. Description:
Tracks manual delivery and pickup processes for MSME orders. Ensures trust and reliability by generating secure delivery codes after payment, notifying customers, and validating handoff when MSMEs/staff confirm delivery or pickup. Integrates with Order, Payment, Notification, and Messaging Services to complete the fulfillment loop.

2. Features:
- Generate secure delivery code after payment confirmation
- Notify customer with delivery code and instructions
- Track delivery method: `pickup` or `deliver_to_customer`
- Validate delivery code when MSME/staff confirms handoff
- Emit delivery lifecycle events (`delivery_code_generated`, `delivery_confirmed`)
- Link delivery to order, session, and bot instance
- Support anonymous users via `user_phone`

3. Schema:
Table: delivery_service.deliveries
- id: UUID (PK)
- order_id: UUID (FK → order_service.orders.id)
- user_phone: TEXT (indexed)
- user_id: UUID (FK → auth_service.users.id, nullable)
- business_id: UUID (FK → business_service.businesses.id)
- delivery_method: ENUM('pickup', 'deliver_to_customer')
- delivery_code: TEXT (unique, indexed)
- status: ENUM('pending', 'code_sent', 'confirmed')
- confirmed_by: TEXT (nullable)                     -- Staff or bot ID
- metadata: JSONB
- created_at: TIMESTAMP
- updated_at: TIMESTAMP

4. Routes:
POST   /delivery/initiate/{order_id}        → Generate delivery code after payment
GET    /delivery/{id}                       → Get delivery details
GET    /delivery/order/{order_id}           → Get delivery by order
POST   /delivery/{id}/confirm               → Confirm delivery using code
GET    /delivery/user/{user_phone}          → List deliveries by phone

5. External Outreach:
- Listens for `payment_success` from Payment Service to trigger delivery code generation
- Sends delivery code via Notification Service
- Publishes delivery lifecycle events to Audit and Messaging Services
- May validate order and user via Order and Session Services

6. Background Work:
- Cleanup of expired or unused delivery codes
- Audit sync for delivery lifecycle
- Optional reminder triggers for pending deliveries
- Reconciliation jobs for unconfirmed deliveries

10. Scalability Readiness:
- **Current Target (1–500 MSMEs):**
  - Indexed queries on `order_id`, `user_phone`, `delivery_code`
  - Basic lifecycle events and cleanup routines

- **Ready for 1,000 MSMEs:**
  - Redis cache for delivery code lookup
  - Horizontal scaling with Docker + Kubernetes
  - Partitioned delivery table by business_id
  - Circuit breakers for Notification and Order calls

- **Path to 10,000+ MSMEs:**
  - Sharded delivery table by region or business_id
  - Event-driven architecture with Kafka/RabbitMQ
  - Read replicas for analytics queries
  - Autoscaling policies based on delivery volume
  - Observability stack (Prometheus + Grafana)
