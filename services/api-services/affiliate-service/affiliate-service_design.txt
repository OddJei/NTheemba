API SERVICE DESIGN: AFFILIATE SERVICE

1. Description:
Manages affiliate identities, codes, and their linkage to users and MSMEs. Provides APIs for generating, validating, and resolving affiliate codes. Ensures contributors and affiliates can be uniquely identified and tied to onboarding events. Works in tandem with Affiliate Tracker Service for reward logic, and integrates with Index/Search Service for discoverability.

2. Features:
- Register new affiliates (linked to users in Auth Service)
- Generate unique affiliate codes (service-driven, DB-enforced uniqueness)
- Validate affiliate codes during MSME registration
- Resolve affiliate code → affiliate details
- Track affiliate status (active, suspended, expired)
- Expose affiliate metadata for Business, Tracker, and Index/Search Services
- Emit lifecycle events (`affiliate_registered`, `affiliate_updated`, `affiliate_suspended`) to Index/Search Service
- Reindex endpoint for recovery (bulk re-publish affiliates to Index/Search Service)

3. Schema:
Table: affiliate_service.affiliates
- id: UUID (PK)
- user_id: UUID (FK → auth_service.users.id)
- code: TEXT (unique, indexed)                  -- Generated by service, uniqueness enforced by DB
- status: ENUM('active', 'suspended', 'expired')
- created_at: TIMESTAMP
- updated_at: TIMESTAMP

Table: affiliate_service.affiliate_metadata
- id: UUID (PK)
- affiliate_id: UUID (FK → affiliate_service.affiliates.id)
- description: TEXT
- region: TEXT
- tags: TEXT[] (optional, for search relevance)
- notes: TEXT
- created_at: TIMESTAMP

4. Code Generation Strategy:
- Codes are generated by the Affiliate Service at registration or on demand.
- Format can include prefix + random/serial component (e.g., `AFF-XYZ123`).
- Service ensures format consistency and retry logic on collision.
- Database enforces uniqueness with a `UNIQUE INDEX` on `affiliates.code`.

5. Routes:
POST   /affiliate/register             → Register new affiliate (linked to user)
POST   /affiliate/generate             → Generate new affiliate code
GET    /affiliate/{code}               → Resolve affiliate code details
GET    /affiliate/{id}/metadata        → Get affiliate metadata
PUT    /affiliate/{id}/status          → Update affiliate status
POST   /affiliate/reindex              → Re-publish all affiliates to Index/Search Service

6. External Outreach:
- Validates affiliate codes for Business Service during MSME registration
- Publishes affiliate lifecycle events (`affiliate_registered`, `affiliate_updated`, `affiliate_suspended`) to Index/Search Service
- Publishes affiliate creation/update/suspension events to Audit Service
- Shares affiliate metadata with Affiliate Tracker Service
- May notify Notification Service on affiliate approval or suspension

7. Background Work:
- Expiry checks for affiliate codes
- Cleanup of inactive or suspended affiliates
- Audit sync for affiliate lifecycle events
- Reindex jobs for Index/Search Service (periodic or on-demand)

8. Scaling Readiness:
- **Current Target (1–500 affiliates):**
  - Single instance deployment with connection pooling
  - Indexed queries on `code` and `user_id`
  - Basic expiry checks for affiliate codes

- **Ready for 1,000 affiliates:**
  - Stateless service design with Redis for pub/sub events
  - Horizontal scaling with Docker + Kubernetes
  - Partitioned affiliate metadata for faster lookups
  - Circuit breakers for Business, Notification, and Index/Search Service calls

- **Path to 10,000+ affiliates:**
  - Sharded `affiliates` table (by region or campaign)
  - Event-driven architecture with Kafka/RabbitMQ for affiliate lifecycle events
  - Read replicas for analytics queries
  - Autoscaling policies based on affiliate registration and validation load
  - Observability stack (Prometheus + Grafana) for proactive scaling

9. Folder Structure (Layered Scaffolding):
└── affiliate-service/
    ├── alembic/
    ├── alembic.ini
    ├── controllers/          # Route handlers (e.g., register, generate, reindex)
    ├── services/             # Affiliate logic (e.g., code generation, validation)
    ├── models/               # SQLAlchemy models for affiliates, metadata
    ├── routes/               # Route declarations
    ├── jobs/                 # Background workers (e.g., expiry checks, reindex jobs)
    ├── events/               # Redis/pub-sub emitters (e.g., affiliate_registered)
    ├── utils/                # Code generator, validators
    ├── config/               # TTLs, code format rules
    ├── Dockerfile
    └── main.py

10. Alembic Migrations:
- `alembic init alembic`
- `alembic revision --autogenerate -m "init affiliate schema"`
- `alembic upgrade head`
- Migration history stored in `alembic/versions/`
