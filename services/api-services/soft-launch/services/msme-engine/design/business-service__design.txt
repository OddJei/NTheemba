BUSINESS SERVICE — FINAL DESIGN OVERVIEW

Purpose:
Manages MSME registration, business profiles, subscriptions, and contributor-linked metadata. Anchors MSME identity across the platform and links businesses to products, staff, delivery zones, and affiliate impact. Emits onboarding events for downstream automation and referral tracking. Integrates with Payment Service for subscription activation and renewal, and with Index/Search Service for discoverability.

Core Features:
- Register new MSMEs with business and user details
- Manage business profile (name, location, category, logo)
- Handle subscription plans and renewal logic
- Track MSME onboarding source via referral codes
- Define delivery locations for product fulfillment
- Route newly registered MSMEs to onboarding flows
- Expose business metadata for product, messaging, and analytics services
- Initiate subscription payments via Payment Service
- Activate or extend subscriptions on payment confirmation
- Emit lifecycle events (msme_registered, msme_updated, msme_suspended) to Index/Search Service
- Reindex endpoint for recovery (bulk re-publish MSMEs to Index/Search Service)
- Lookup business profile using phone number (for chat-based flows)

Onboarding Logic:
- During MSME registration, the service checks for referral codes:
  - If affiliate_id is provided → emits affiliate_onboarded to Affiliate Event Service
  - If referred_by_msme_code is provided → emits msme_referred to MSME Referral Tracker Service
  - If no code is provided → emits msme_registered to Index/Search Service
- This enables clean tracking of onboarding source and contributor/referrer impact

Schema:
Table: business_service.businesses
- id: UUID (PK)
- name: TEXT
- owner_id: UUID (FK → auth_service.users.id)
- location: TEXT
- category: TEXT
- logo_url: TEXT
- affiliate_id: TEXT (optional)
- referred_by_msme_code: TEXT (optional)
- subscription_plan: TEXT
- subscription_expiry: TIMESTAMP
- delivery_locations: JSONB
- tags: TEXT[] (optional)
- is_active: BOOLEAN
- created_at: TIMESTAMP
- updated_at: TIMESTAMP

Table: business_service.business_subscriptions
- id: UUID (PK)
- business_id: UUID (FK → business_service.businesses.id)
- plan: TEXT
- start_date: TIMESTAMP
- end_date: TIMESTAMP
- status: ENUM('active', 'expired', 'cancelled', 'pending_payment')

Table: business_service.msme_codes
- id: UUID (PK)
- business_id: UUID (FK → business_service.businesses.id)
- code: TEXT (unique, indexed)
- created_at: TIMESTAMP
- expires_at: TIMESTAMP (optional)
- usage_count: INTEGER
- max_usage: INTEGER (optional)
- notes: TEXT (optional)

Code Generation Strategy:
- MSME referral codes are generated by the Business Service at registration
- Format: prefix + serial/random (e.g., MSME-00045)
- Retry logic on collision
- Uniqueness enforced by DB index

Routes:
POST   /business/register              → Register new MSME
GET    /business/{id}                  → Get business profile
PUT    /business/{id}                  → Update business details
DELETE /business/{id}                  → Delete business (soft or hard)
POST   /business/{id}/subscribe        → Initiate subscription (calls Payment Service)
GET    /business/{id}/subscription     → Get subscription status
GET    /business/{id}/metadata         → Fetch business metadata for other services
GET    /business/phone/{phone_number}  → 🔍 Lookup business by phone (for chat flows)
POST   /business/reindex               → Re-publish all MSMEs to Index/Search Service

External Outreach:
- Sends onboarding triggers to Notification Service
- Publishes registration and update events to Audit Service
- Publishes MSME lifecycle events to Index/Search Service
- Emits affiliate_onboarded to Affiliate Event Service
- Emits msme_referred to MSME Referral Tracker Service
- Shares metadata with Product, Messaging, and Analytics Services
- Validates user identity via Auth Service
- Emits msme_onboarded event to Affiliate Tracker Service
- Calls Payment Service to initiate subscription payments
- Listens for payment_success and payment_failed events

Background Work:
- Daily subscription expiry checks
- Auto-renewal or reminder triggers
- Cleanup of inactive or orphaned business records
- Audit sync for registration and updates
- Subscription activation/extension on payment_success
- Grace period handling on payment_failed
- Reindex jobs for Index/Search Service

Scaling Readiness:
Current Target (1–500 MSMEs):
- Single instance deployment with connection pooling
  - Indexed queries on business_id, affiliate_id, referred_by_msme_code
- Basic background jobs for expiry and reminders

Ready for 1,000 MSMEs:
- Stateless service design with Redis for pub/sub events
- Horizontal scaling with Docker + Kubernetes
- Partitioned subscription checks
- Circuit breakers for Payment, Notification, and Index/Search calls

Path to 10,000+ MSMEs:
- Sharded businesses and msme_codes tables
- Event-driven architecture with Kafka/RabbitMQ
- Read replicas for analytics queries
- Autoscaling policies based on queue depth and subscription volume
- Observability stack (Prometheus + Grafana)
