1. Description:
Manages temporary product selections for users interacting with MSME bots or storefronts. Enables multi-item carts, quantity adjustments, and checkout preparation. Cart Service links to product variants, validates stock availability, and supports session-based persistence for anonymous users. It is essential for conversational commerce and bot-driven ordering.

2. Features:
- Add product variants to cart
- Update quantity or remove items
- Link cart to session or user identity
- Validate stock availability before checkout
- Emit cart lifecycle events (`cart_created`, `cart_updated`, `cart_cleared`)
- Prepare cart payload for Order Service
- Support anonymous carts via `user_phone`

3. Schema:
Table: cart_service.carts
- id: UUID (PK)
- session_id: UUID (FK → user_bot_session_service.sessions.id)
- user_phone: TEXT (indexed, nullable)
- user_id: UUID (FK → auth_service.users.id, nullable)
- business_id: UUID (FK → business_service.businesses.id)
- status: ENUM('active', 'checked_out', 'abandoned')
- metadata: JSONB
- created_at: TIMESTAMP
- updated_at: TIMESTAMP

Table: cart_service.cart_items
- id: UUID (PK)
- cart_id: UUID (FK → cart_service.carts.id)
- variant_id: UUID (FK → catalog_service.product_variants.id)
- quantity: INTEGER
- unit_price: DECIMAL(12,2)
- subtotal: DECIMAL(12,2)
- created_at: TIMESTAMP

4. Routes:
POST   /cart/create                      → Create new cart
POST   /cart/{id}/add                    → Add item to cart
PUT    /cart/{id}/update                 → Update item quantity
DELETE /cart/{id}/remove/{item_id}       → Remove item from cart
GET    /cart/session/{session_id}        → Get cart by session
GET    /cart/user/{user_phone}           → Get cart by phone
POST   /cart/{id}/checkout               → Prepare cart for order

5. External Outreach:
- Validates product and variant via Catalog Service
- Checks stock availability via Inventory Service
- Emits cart lifecycle events to Messaging and Notification Services
- Shares cart metadata with Order Service
- May validate session via User-Bot Session Service

6. Background Work:
- Cleanup of abandoned carts
- Audit sync for cart lifecycle
- Optional cart reminder triggers
- Stock revalidation before checkout

10. Scalability Readiness:
- **Current Target (1–500 MSMEs):**
  - Indexed queries on `session_id`, `user_phone`, `business_id`
  - Basic cart lifecycle events and cleanup routines

- **Ready for 1,000 MSMEs:**
  - Redis cache for session → cart lookup
  - Horizontal scaling with Docker + Kubernetes
  - Partitioned cart tables by business_id
  - Circuit breakers for Inventory and Catalog calls

- **Path to 10,000+ MSMEs:**
  - Sharded cart tables by region or business_id
  - Event-driven architecture with Kafka/RabbitMQ
  - Read replicas for analytics queries
  - Autoscaling policies based on cart volume
  - Observability stack (Prometheus + Grafana)
