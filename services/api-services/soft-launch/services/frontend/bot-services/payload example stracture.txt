Absolutely, James. Here's a full simulation of the **inbound and outbound payloads** for each of the three core services in your bot architecture:

- **Ingress Service**
- **Intent Service**
- **Bot Service** (Default or Custom—same structure, different trees/handlers)

Each service receives a payload, enriches or transforms it, and publishes a new version downstream. Only the `current_event` block evolves; all other metadata remains stable.

---

## 1️⃣ Ingress Service

### 📥 Inbound Payload (from channel)
```json
{
  "request_id": "req_00123",
  "to": "ntb_default",
  "from": "097xxxxxxx",
  "message": "I want to buy a solar panel",
  "meta": {
    "platform": "wa"
  }
}
```

## 3️⃣ Bot Service (Default or Custom)

### 📥 Inbound Payload (from default_queue or custom_queue)
Same as Intent outbound payload.

### 📤 Outbound Payload (to reply_queue)
```json
{
  ...,
  "meta": {
    ...,
    "current_event": {
      "event_id": "evt_003",
      "timestamp": "2025-10-22T18:02:00Z",
      "status": "pending",
      "current_node": "serve_products",
      "possible_next_nodes": {
        "select_category": "serve_products",
        "view_cart": "inspect_cart_item"
      },
      "intent": "select_category",
      "next_node": "serve_products",

        "selected_category": "Solar",

```

## 🧠 Summary

| Service        | Inbound Source         | Outbound Target         | Enrichment Focus |
|----------------|------------------------|--------------------------|------------------|
| Ingress        | Channel (wa/sms/web)   | `resolved_payload` queue | Full metadata + current_event stub |
| Intent         | `resolved_payload`     | `default_queue` / `custom_queue` | `intent`, `next_node`, `confidence` |
| Bot (Default/Custom) | `default_queue` / `custom_queue` | `reply_queue` | `node_executed`, `tree_state`, `action_status` |
