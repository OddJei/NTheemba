# 🔄 Concise E2E Flow (Updated)

### **Actors**
- **Affiliate** → creates and shares the first-token/code.  
- **Static Landing Service** → public page/UI that parses tokens + browser meta.  
- **Affiliate Engine** → validates, issues second-token, tracks events.  
- **WhatsApp** → channel for buyer interaction.  
- **Business Bot** → resolves second-token, serves product details.  

---

### **Step 1: First-token (persistent)**
- `AffiliateLink.code` generated by Affiliate Engine.  
- Affiliate Engine serves this token to web/bot.  
- Web/bot adds the **base URL** → `https://nteemba.com/a/{code}`.  
- Token may carry optional browser meta (UX-only fields):  
  - `session_id`, `user_phone`, `ip`, `user_agent`, `referer`, `accept-language`, `client-hints`.

---

### **Step 2: Public Click**
- User clicks affiliate link → browser opens **Static Landing Service**.  
- Static service automatically parses:  
  - `first-token` from URL.  
  - Optional browser meta (collected silently).  
- Static service calls Affiliate Engine:  
  - `GET /a/{code}/resolve`  
  - Passes token + optional context (meta).

---

### **Step 3: Validation**
- Affiliate Engine looks up `AffiliateLink`.  
- Calls:  
  - MSME API → `/business/{id}/entitlements` (check subscription active).  
  - Catalog API → `/catalog/product/{id}` (check product availability).  
- If invalid → returns `{status: unavailable, reason}`.

---

### **Step 4: Second-token (short-lived, single-use)**
- If valid → Affiliate Engine creates `AffiliateToken`:  
  - Tied to `affiliate_id`, `business_id`, `product_id`, originating `first-token`.  
  - `used = false`, `expires_at = TTL (e.g., 10m)`.  
  - Guaranteed unique + single-use enforced.

---

### **Step 5: Response to Static Service**
- Engine returns JSON:  
  - `availability` (true/false).  
  - `token` + `token_message` (e.g., `ace:xxxx`).  
  - `whatsapp_url` (prefilled with `ace:SECOND_TOKEN:: Hello🖐/nI was Directed here`).  
  - Optional product preview (name, price, thumbnail).  
- Static service either:  
  - Redirects user directly to WhatsApp.  
  - Or shows a static CTA (button → “Chat on WhatsApp”).

---

### **Step 6: WhatsApp Flow**
- User opens WhatsApp with `ace:SECOND_TOKEN` prefilled.  
- Sends message to business number.

---

### **Step 7: Bot Resolution**
- Business Bot receives message.  
- Bot extracts token (`ace:xxxx`).  
- Bot calls secure engine endpoint:  
  - `POST /token/resolve` with token + auth.  
- Engine verifies:  
  - Token exists, not expired, not used.  
  - `business_id` matches caller.  
- Marks token as `used`. 
- record unique number/customer 
- Returns product details:  
  - `{id, name, price, product_url, affiliate_id, campaign}`.  
- Bot replies to buyer with formatted product message.

---

### **Step 8: Telemetry & Audit**
- Engine records:  
  - `AffiliateClick` (browser event).  
  - `AffiliateEvent` (token resolution).  
  - `AffiliateEarning` (commission attribution).  
- Uses `affiliate_id` for performance/earnings tracking.  
- Implementation references: `models.py`, `main.py`, `schemas.py`, `migration alembic/versions/add_affiliate_tokens.py`.

---

### **Security & Policy**
- Second-token = **single-use + TTL + business binding**.  
- Bot endpoint requires **auth**.  
- Engine logs all resolutions.  
- Rate-limit token resolution to prevent abuse.  

---

👉 In plain words:  
- Affiliates share a **first-token link**.  
- Static page parses it + browser meta.  
- Engine validates product/business, issues a **second-token**.  
- User is redirected to WhatsApp with the token.  
- Bot resolves token → shows product info.  
- Engine logs everything for compliance + earnings.
