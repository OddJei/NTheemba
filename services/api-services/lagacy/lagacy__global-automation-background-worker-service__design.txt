Global Automation & Background Worker Service (GABS)

1. Description:
Coordinates scheduled tasks, background jobs, and automation flows across all services. Each microservice may have its own internal automation, but GABS handles global timing, cross-service orchestration, and centralized job monitoring. It enforces subscription expiry logic, triggers affiliate payouts, milestone checks, and analytics syncs.

2. Features:
- Trigger scheduled jobs across services (e.g. APS payout, weekly notifications)
- Monitor job status and retry failures
- Emit system-wide events (e.g. MonthlyPoolCycleStarted, AffiliateCycleEnded)
- Run background workers for:
  - milestone checks
  - subscription rewards
  - subscription expiry enforcement
  - leaderboard snapshots
  - analytics sync
- Maintain job queue and execution logs
- Support cron-based and event-driven scheduling
- Emit enforcement events to BotInstanceService, ProductCatalogService, and PublicModeService

3. Schema:
Table: gabs.job_queue
- id: UUID (PK)
- job_type: TEXT
- target_service: TEXT
- payload: JSONB
- status: ENUM('pending', 'running', 'completed', 'failed')
- scheduled_for: TIMESTAMP
- executed_at: TIMESTAMP
- retry_count: INTEGER

Table: gabs.job_log
- id: UUID (PK)
- job_id: UUID (FK → gabs.job_queue.id)
- log_message: TEXT
- created_at: TIMESTAMP

4. Routes:
POST   /job/schedule                          → Schedule a new job
POST   /job/trigger                           → Trigger job immediately
GET    /job/status/{job_id}                   → Get job status
GET    /job/queue                             → View pending jobs
POST   /job/retry/{job_id}                    → Retry failed job
GET    /job/logs/{job_id}                     → View job logs

5. Background Workers:
- APS payout trigger (every 6 months)
- APS weekly notification batch
- MRTS milestone check (daily)
- SubscriptionService reward trigger
- SubscriptionService expiry enforcement (daily)
- AnalyticsService sync (hourly)
- Referral leaderboard snapshot (weekly)

6. Enforcement Logic:
Worker: `check_expired_subscriptions.py`
- Queries SubscriptionService for expired MSMEs
- Triggers:
  - BotInstanceService → deactivate bot
  - ProductCatalogService → hide products
  - PublicModeService → restrict public access
- Emits `SubscriptionEnforcementTriggered(msme_id, status="restricted")`
- Logs enforcement status in `job_log`

7. Folder Structure:
└── global-automation-service/
    ├── alembic/
    ├── alembic.ini
    ├── controllers/          # Route handlers (e.g., schedule, trigger)
    ├── services/             # Job orchestration logic
    ├── models/               # SQLAlchemy models for job_queue, job_log
    ├── routes/               # Route declarations
    ├── jobs/                 # Background workers (e.g., APS payout, subscription enforcement)
    │   ├── check_expired_subscriptions.py
    ├── events/               # Redis/pub-sub emitters (e.g., enforcement triggered)
    │   ├── subscription_enforcement_triggered.py
    ├── utils/                # Date helpers, retry logic
    ├── config/               # Job TTLs, cron definitions
    ├── Dockerfile
    └── main.py

8. Alembic Migrations:
- alembic init alembic
- alembic revision --autogenerate -m "init job queue schema"
- alembic upgrade head
- Migration history stored in `alembic/versions/`

10. Scaling Readiness:
- **Current Target (1–500 jobs/month):**
  - Simple cron scheduler
  - Manual retry logic
  - Basic job logs

- **Ready for 1,000+ jobs/month:**
  - Redis-backed job queue
  - Async worker pool
  - Job priority levels

- **Path to 10,000+ jobs/month:**
  - Distributed job runners
  - Sharded job queue
  - Event-driven orchestration via Kafka or NATS
  - Job dependency graph and DAG execution
