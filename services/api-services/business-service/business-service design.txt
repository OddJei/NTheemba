API SERVICE DESIGN: BUSINESS SERVICE

1. Description:
Manages MSME registration, business profiles, subscriptions, and contributor-linked metadata. It anchors MSME identity across the platform and links businesses to products, staff, delivery zones, and affiliate impact. Emits onboarding events for downstream automation and referral tracking. Integrates with Payment Service for subscription activation and renewal, and with Index/Search Service for discoverability.

2. Features:
- Register new MSMEs with business and user details
- Manage business profile (name, location, category, logo)
- Handle subscription plans and renewal logic
- Link MSMEs to contributors via affiliate codes
- Track MSME-to-MSME referrals via referral codes
- Define delivery locations for product fulfillment
- Route newly registered MSMEs to onboarding flows
- Expose business metadata for product, messaging, and analytics services
- Initiate subscription payments via Payment Service
- Activate or extend subscriptions on payment confirmation
- Emit lifecycle events (`msme_registered`, `msme_updated`, `msme_suspended`) to Index/Search Service
- Reindex endpoint for recovery (bulk re-publish MSMEs to Index/Search Service)

3. Schema:
Table: business_service.businesses
- id: UUID (PK)
- name: TEXT
- owner_id: UUID (FK → auth_service.users.id)
- location: TEXT
- category: TEXT
- logo_url: TEXT
- affiliate_code: TEXT (optional)               -- Contributor or affiliate who referred
- referred_by_msme_code: TEXT (optional)        -- MSME-to-MSME referral code
- subscription_plan: TEXT
- subscription_expiry: TIMESTAMP
- delivery_locations: JSONB
- tags: TEXT[] (optional, for search relevance)
- is_active: BOOLEAN
- created_at: TIMESTAMP
- updated_at: TIMESTAMP

Table: business_service.business_subscriptions
- id: UUID (PK)
- business_id: UUID (FK → business_service.businesses.id)
- plan: TEXT
- start_date: TIMESTAMP
- end_date: TIMESTAMP
- status: ENUM('active', 'expired', 'cancelled', 'pending_payment')

Table: business_service.msme_codes
- id: UUID (PK)
- business_id: UUID (FK → business_service.businesses.id)
- code: TEXT (unique, indexed)                  -- Generated by service, uniqueness enforced by DB
- created_at: TIMESTAMP
- expires_at: TIMESTAMP (optional)
- usage_count: INTEGER
- max_usage: INTEGER (optional)
- notes: TEXT (optional)

4. Code Generation Strategy:
- MSME referral codes are generated by the Business Service at registration.
- Format can include prefix + serial/random component (e.g., `MSME-00045`).
- Service ensures format consistency and retry logic on collision.
- Database enforces uniqueness with a `UNIQUE INDEX` on `msme_codes.code`.

5. Routes:
POST   /business/register              → Register new MSME
GET    /business/{id}                  → Get business profile
PUT    /business/{id}                  → Update business details
POST   /business/{id}/subscribe        → Initiate subscription (calls Payment Service)
GET    /business/{id}/subscription     → Get subscription status
GET    /business/{id}/metadata         → Fetch business metadata for other services
POST   /business/reindex               → Re-publish all MSMEs to Index/Search Service

6. External Outreach:
- Sends onboarding triggers to Notification Service
- Publishes registration and update events to Audit Service
- Publishes MSME lifecycle events (`msme_registered`, `msme_updated`, `msme_suspended`) to Index/Search Service
- Links affiliate codes via Affiliate Service
- Shares metadata with Product, Messaging, and Analytics Services
- May validate user identity via Auth Service
- Emits `msme_onboarded` event to Affiliate Tracker Service
- Calls Payment Service to initiate subscription payments
- Listens for `payment_success` and `payment_failed` events from Payment Service

7. Background Work:
- Daily subscription expiry checks
- Auto-renewal or reminder triggers
- Cleanup of inactive or orphaned business records
- Audit sync for registration and updates
- Subscription activation/extension on `payment_success` events
- Grace period handling on `payment_failed` events
- Reindex jobs for Index/Search Service (periodic or on-demand)

8. Scaling Readiness:
- **Current Target (1–500 MSMEs):**
  - Single instance deployment with connection pooling
  - Indexed queries on `business_id`, `affiliate_code`, `referred_by_msme_code`
  - Basic background jobs for expiry and reminders

- **Ready for 1,000 MSMEs:**
  - Stateless service design with Redis for pub/sub events
  - Horizontal scaling with Docker + Kubernetes
  - Partitioned subscription checks for faster expiry handling
  - Circuit breakers for Payment, Notification, and Index/Search Service calls

- **Path to 10,000+ MSMEs:**
  - Sharded `businesses` and `msme_codes` tables (by region or business_id)
  - Event-driven architecture with Kafka/RabbitMQ for onboarding and subscription events
  - Read replicas for analytics queries
  - Autoscaling policies based on queue depth and subscription volume
  - Observability stack (Prometheus + Grafana) for proactive scaling

9. Folder Structure (Layered Scaffolding):
└── business-service/
    ├── alembic/
    ├── alembic.ini
    ├── controllers/          # Route handlers (e.g., register, subscribe, reindex)
    ├── services/             # Business logic (e.g., subscription validation)
    ├── models/               # SQLAlchemy models for businesses, subscriptions, msme_codes
    ├── routes/               # Route declarations
    ├── jobs/                 # Background workers (e.g., expiry checks, reindex jobs)
    ├── events/               # Redis/pub-sub emitters (e.g., onboarding, subscription, msme_registered)
    ├── utils/                # Validation, referral code generator
    ├── config/               # Plan definitions, TTLs
    ├── Dockerfile
    └── main.py

10. Alembic Migrations:
- `alembic init alembic`
- `alembic revision --autogenerate -m "init business schema"`
- `alembic upgrade head`
- Migration history stored in `alembic/versions/`
